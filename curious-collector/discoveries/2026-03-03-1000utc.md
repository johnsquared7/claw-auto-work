## 🎯 Key Findings

### 1. Tuva Project — Healthcare Data Modeling with dbt
**URL:** https://github.com/tuva-health/tuva

The Tuva Project is an open-source **healthcare data transformation toolkit** built on dbt (data build tool).

- **Core Data Model:** Standardized healthcare data model for claims, clinical, and social determinants
- **Claims Preprocessing:** Built-in transforms for healthcare claims data
- **Data Quality Tests:** Pre-built data quality checks specific to healthcare
- **Terminology Sets:** Standard medical vocabularies mapped and ready to use
- **Works with:** PostgreSQL, Snowflake, BigQuery, DuckDB (local dev)

```python
# Quick start with DuckDB
pip install dbt-duckdb dbt-core
# Then run tuva's dbt package
```

**Why it's unique:** Unlike generic ETL tools, Tuva is purpose-built for **healthcare data** with NHS-relevant concepts (patients, encounters, conditions, procedures).

**Relevance for John:** High — could standardize NHS data pipelines, similar to what John's team does with hospital admissions data

### 2. Aiven SQL Query Optimizer — Free Online Tool
**URL:** https://aiven.io/tools/sql-query-optimizer

A completely **free online SQL optimizer** for PostgreSQL and MySQL.

- Paste your SQL query
- Get **index recommendations**
- Get **SQL rewrite suggestions**
- Built-in query formatter

**Why it's unique:** Most SQL optimizers are expensive enterprise tools. This is free, no signup required for basic use, and actually helpful.

**Relevance for John:** High — quick way to optimize slow NHS SQL queries without installing anything

### 3. Google CQL — Clinical Quality Language
**URL:** https://github.com/google/cql

An experimental **Clinical Quality Language execution engine** for analyzing FHIR healthcare data at scale.

- Write clinical quality measures in CQL (a FHIR standard)
- Execute against FHIR datasets
- Used by healthcare systems for quality reporting

```cql
// Example CQL query
define "Patients with Diabetes":
  [Condition: Code in "Diabetes Mellitus"] Diabetes
    where Diabetes.clinicalStatus = 'active'
```

**Why it's relevant:** If NHS moves toward FHIR (they're adopting it), this could be relevant for standardized clinical queries.

**Relevance for John:** Medium — future-looking, but worth watching

### 4. Mercury Framework — Automated Reports + Email
**URL:** https://mljar.com/blog/automated-reports-python/

Mercury turns Jupyter notebooks into **interactive web apps** with automatic report generation.

- Write reports in Jupyter notebooks
- Schedule execution (daily/weekly)
- **Email reports automatically** as PDF
- Web UI for non-technical users to run reports

```python
# In your notebook
import mercury as mr

# Add interactive widgets
df = mr.DataFrame(data)
```

**Why it's unique:** Combines notebook analytics with automation — perfect for recurring NHS reports.

**Relevance for John:** High — could replace manual Power BI refresh + email workflow
